# RentGuard 실제 문서 샘플 확보 가이드

실제 계약 판단용 데이터셋이 아니라, 문서 추출기의 형식 대응력을 검증하기 위한 테스트 세트를 만든다. 본인 문서 또는 제공자가 테스트 사용에 동의한 문서만 사용한다.

## 공식 확보 경로

| 문서 | 공식 경로 | 확보 방법 | 참고 |
|---|---|---|---|
| 등기사항증명서 | 대한민국 법원 인터넷등기소 | 부동산 주소 검색 후 열람 또는 발급 | 말소사항 포함/현재 유효사항, 토지/건물/집합건물을 섞는다. |
| 건축물대장 | 정부24 건축물대장 발급·열람 | 주소 검색 후 인터넷 발급 | 일반건축물, 집합건축물 표제부, 전유부를 구분한다. |
| 임대차계약서 양식 | 법무부 주택임대차표준계약서 | 원본 게시용 PDF 또는 사용용 서식 다운로드 | 빈 양식은 레이아웃 테스트용이며 실제 기입 데이터는 아니다. |
| 작성된 임대차계약서 | 본인 또는 동의한 지인 | 스캔 또는 PDF 저장 후 익명화 | 부동산 카페·블로그의 타인 계약서를 무단 수집하지 않는다. |

공식 링크:

- 인터넷등기소: https://www.iros.go.kr/
- 정부24 건축물대장: https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=15000000098&tp_seq=03
- 법무부 주택임대차표준계약서: https://moj.go.kr/moj/314/subview.do

## 최소 권장 테스트 구성

### 등기사항증명서

- 집합건물 3건, 일반 건물 2건, 토지 1건
- 현재 유효사항 2건, 말소사항 포함 4건
- 권리사항 없음, 근저당 1건, 근저당 여러 건
- 가능하면 압류·가압류·신탁이 표시된 문서
- 원본 디지털 PDF와 휴대전화 촬영/스캔본을 각각 포함

### 건축물대장

- 일반건축물대장
- 집합건축물대장 표제부
- 집합건축물대장 전유부
- 위반건축물 표기가 없는 문서와 있는 문서
- 다세대주택, 다가구주택, 공동주택 등 용도 차이 포함

### 임대차계약서

- 법무부 표준계약서와 공인중개사 사무소 양식
- 전세, 보증부 월세, 월세
- 컴퓨터 작성본과 손글씨/도장 포함 스캔본
- 특약이 없는 문서와 여러 줄인 문서

## 익명화 규칙

원본은 저장소 밖에 보관하고 복사본만 익명화한다. 다음 값은 반드시 가린다.

- 주민등록번호, 외국인등록번호
- 전화번호, 계좌번호
- 서명, 도장, QR 코드, 발급확인번호
- 상세 주소 중 테스트에 필요하지 않은 부분
- 개인 또는 법인을 직접 식별할 수 있는 고유번호

다만 교차검증 관계는 유지해야 한다. 예를 들어 등기 소유자와 계약서 임대인이 같은 사례라면 두 문서 모두 같은 가명으로 바꾸고, 주소도 세 문서에서 같은 가상 주소로 바꾼다. 금액은 원본 대신 일정 비율로 변환해도 되지만 등기부·계약서·정답 파일 사이에서는 일관되어야 한다.

## 파일 배치

현재 개발 PC에서는 원본과 익명화 사본을 다음 경로로 분리한다. 프로젝트가 OneDrive 아래에 있으므로 원본은 프로젝트 폴더에 넣지 않는다.

### 익명화 전 원본

```text
C:\RentGuard-private-raw\case-001\
  registry-original.pdf
  building-ledger-original.pdf
  lease-contract-template.pdf
```

### 개발용 익명화 사본

```text
RentGuard\local-fixtures\case-001\
  registry.pdf
  building-ledger.pdf
  lease-contract.pdf
  expected.json
```

지금 발급받은 등기사항증명서 원본의 파일명은 `registry-original.pdf`로 변경한다. 익명화가 끝난 뒤 생성한 별도 사본만 `registry.pdf`라는 이름으로 개발용 폴더에 넣는다.

`local-fixtures/`는 `.gitignore`에 포함한다. `expected.json`에는 직접 확인한 정답만 기록하고, 자동 추출 결과를 그대로 정답으로 복사하지 않는다.

## 회전된 PDF 전처리

원본 페이지 내용이 옆으로 저장된 문서는 원본을 수정하지 않고 새 사본을 만든다. 다음 명령은 `/Rotate` 메타데이터만 바꾸지 않고 새 페이지에 내용을 실제로 회전 배치한다.

```bat
cd apps\api
.venv\Scripts\python -m app.services.pdf_rotation ^
  C:\RentGuard-private-raw\case-001\building-ledger-original.pdf ^
  C:\RentGuard-private-raw\case-001\building-ledger-upright-private.pdf ^
  --rotation 270
```

출력 파일이 이미 있거나 입력과 출력 경로가 같으면 작업을 중단한다. 링크, 주석, PDF 입력 폼이 있는 문서는 별도 보존 절차가 필요하다.

## CASE-001 익명화 사본 생성

정방향 건축물대장까지 준비한 뒤 저장소 루트에서 아래 명령을 실행한다.

```bat
apps\api\.venv\Scripts\python scripts\prepare_case_001.py
```

이 스크립트는 세 문서에서 식별 정보를 가상 값으로 교체하고, 마스킹 결과를 이미지 전용 PDF로 다시 만든다. 따라서 원본 텍스트 레이어·주석·메타데이터는 개발용 사본에 남지 않는다. 생성 결과와 사람이 확인할 기준값은 `local-fixtures\case-001\`에 저장되며, 기존 결과 파일이 있으면 덮어쓰지 않고 중단한다.

좌표 프로필은 현재 CASE-001 원본 레이아웃 전용이다. 다른 형식의 문서를 추가할 때는 별도 프로필을 만들고, 생성된 모든 페이지를 눈으로 확인한 다음 OCR 결과와 `expected.json`을 대조한다.
